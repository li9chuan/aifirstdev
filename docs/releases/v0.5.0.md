# v0.5.0

邮件模块改为单 owner、单组投递和 Mail 自主管理领取；RDB 保留未解决写入，修复失败后淘汰和关闭重试导致的状态回退。

## 主要变更

- 每个邮件命名空间只运行一个 Mail owner，独占邮箱、共享源、游标和领取状态。使用 RW 锁、内存缓存、逐封 HashSaver 和异步 RDB 保存，移除 CAS、版本轮询和旧 mail/store。
- 每封 GROUP 邮件只对应一个 group_key；批量选组分别发送，各自产生 MailID，属于多个目标组的用户可收到并领取多封。按服发送也使用业务组，不再设置独立游戏服筛选或组合游标。
- Game/user 的 GroupResolver 每次提供可信组快照并 Forward 到 Mail，所有访问入口检查组资格。普通 Awarder 负责发奖，不要求 Game 幂等。
- 领取使用 claimed、持久化 CD 和内存进行中标记。RPC 进行中或 CD 未到期时拒绝；RPC 超时且 CD 到期后允许客户端再次尝试。
- List 只快照全局和当前组；单封操作直接检查副本，整批领取复用一个邮箱引用。旧 PERSONAL 共享副本加载时恢复其收件目标。
- 加载旧邮箱前先 PERSIST，避免读取期间旧 key TTL 到期。全局和按组游标保留，离组、空组和旧快照不会重置处理进度。
- RDB 非重试失败保留最终意图和错误，后台不自动重试，不写 replay journal。后续显式 Flush 对旧失败项各尝试一次，实际完成后才能安全淘汰；新的 Save/Delete 可替代旧意图。独立失败项不会覆盖原连接重试槽。

## 接口与升级

这是包含接口变更的 0.x 次版本。应用只使用一个根 module 版本：

```text
go get github.com/li9chuan/aifirstdev@v0.5.0
go install github.com/li9chuan/aifirstdev/aifd-tools/cmd/aifd@v0.5.0
```

- service.NewModule 返回 (*Module, error)，通过 Options.DB 注入 RDB，由 service 独占 Manager；user module 不再接收 Mailbox 或 Awarder。
- user.Options.GroupResolver 提供 MailGroupKeys(ctx, user)。客户端自报组不再生效，未配置 resolver 时只访问个人和全局邮件。
- 新发送使用 MailAddRequest.group_key，保留并废弃已发布的多组、游戏服字段；携带旧发送目标字段的请求会被拒绝。已发布字段的编号、类型与方向保留。
- 升级前备份并停止全部旧写入者，禁止新旧 owner 混跑。单组旧邮件及原全局/按组游标可接管；尚有效的旧多组或限服共享邮件必须显式转换或等待过期，恢复不会静默丢弃限制。
- 新 owner 写入后不直接降级回旧 owner；回退使用旧版本对应的数据快照。
- RDB.WaitSize 包含未解决的非重试写入。错误回传后不会清零；Close 保留这些错误。修复后可显式 Flush 已接纳的意图，即使 worker 已关闭；关闭后的 DB 仍拒绝新 Save/Delete。

完整接口、默认配置、生命周期和迁移要求见 [Mail README](../../aifd-plugins/mail/README.md) 与 [RDB README](../../aifd-rdb/README.md)。

## 保持的边界

RDB 接收入队不等于已经落盘；正常关闭要求 Flush 成功。强杀仍可能丢失近期邮件、CD、领取或游标状态。普通 Game 发奖已执行但回包丢失时，CD 到期重试可能重复发奖；Mail 与 Game 没有跨服务资产事务。

业务项目及管理后台、客户端接入需由各自项目单独升级和适配，本次发布不自动修改消费者。
