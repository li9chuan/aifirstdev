# v0.6.0

新增可选的原生 HTTPS/WSS、免费证书自动申请与续期，完善业务接入文档、代码导航和 RDB 选型规则。

## 主要变更

- `aifd-proxy/adapters/httpserver` 显式组合标准 Go HTTP server 与既有 WS handler，提供 plain、manual 和 ACME 三种模式，不依赖 Nginx 或外部续期脚本。
- ACME 使用固定版本 CertMagic，支持 TLS-ALPN-01、账户和证书持久复用、ARI、后台自动续期、私有证书缓存及完整证书组合的原子提交。续期后新握手使用新证书，已有 WSS 连接保持。
- 提供证书准备状态、失败状态及显式关闭流程；缓存损坏拒绝启动，续期失败时保留仍有效的旧证书。
- CA 429/503 遵守 `Retry-After`，失败退避和冷却截止时间原子保存，重启后继续等待；关闭时取消等待并排空持锁任务。
- Go WS transport 新增 `RequireTLS` 和受控 `HTTPClient` 配置；安全 URL 拒绝降级及跨源重定向，标准 HTTP transport 保持证书校验并要求 TLS 1.2 以上。
- 新增[业务接入](../application-integration.md)、[文档与代码导航](../README.md)、[原生入口设计](../native-https-design.md)与可运行示例，校正文档和实际代码的差异。
- 开发与评审规则统一引用[业务持久化选型](../../aifd-rules/skills/feature-development/references/rdb-selection.md)：适用时优先 RDB，保留原生 Redis/Lua 的合理使用空间。普通业务使用 Save，宿主停服调用 Close，Flush 用于特殊场景。

## 升级与接入

```text
go get github.com/li9chuan/aifirstdev@v0.6.0
go install github.com/li9chuan/aifirstdev/aifd-tools/cmd/aifd@v0.6.0
```

- 默认 HTTP/WS 行为保留；HTTPS/WSS 由宿主显式启用，入口、协议、账号与权限仍分别归原模块拥有。
- 已有 WSS 使用者需检查重定向和自定义 HTTPClient：降级、跨源跳转及标准 transport 的 `InsecureSkipVerify` 配置会被拒绝。
- ACME 需要受控域名正确解析、公网 443 可达、接受 CA 协议，并把私有缓存放在版本发布目录之外。先使用 staging 验证，生产使用受信任证书。
- 框架和 CLI 统一升级根 module；业务项目分别升级依赖和规则快照。本次发布不自动修改消费者或业务部署。
- 从 v0.4.x 或更早版本升级时，另读 [v0.5.0](v0.5.0.md) 的邮件接口和数据接管要求。

## 已知边界

- 限流处理依据本实例收到的 CA 响应和本地失败退避；CA 全局配额仍由 CA 判定，本组件不维护跨实例配额账本。
- 首版只支持单机单进程、明确域名和 TLS-ALPN-01；不提供 DNS-01、通配符签发、共享缓存 HA 或跨实例配额协调。
- 本地 Pebble 验证不能替代公开域名的 Let's Encrypt staging、多地点网络可达性和长期生产续期验收；原生桌面运行及安装器另行验证。

完整接入、状态、恢复与测试条件见 [HTTP 入口 README](../../aifd-proxy/adapters/httpserver/README.md) 和[设计说明](../native-https-design.md)。
