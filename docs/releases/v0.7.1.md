# v0.7.1：WebSocket 升级与关闭竞态修复

修复客户端已收到 HTTP 101、服务端仍在完成升级而尚未登记传输连接时，并发 `Server.Close` 可能漏掉这条未认证连接的问题。WebSocket adapter 在登记后再次检查关闭状态，并关闭已跨过关闭快照的连接。

## 兼容性

公共 API、配置、协议、认证策略和存储格式保持不变。框架、CLI 与官方插件仍使用单一根 module 版本；消费者升级到 `github.com/li9chuan/aifirstdev@v0.7.1`，不需要增加业务层关闭补丁或修改生成物。

v0.7.0 的日志与 Stat 迁移要求继续见[原发布说明](v0.7.0.md)。本补丁不扩大 TLS/ACME、数据处理或业务功能范围。

## 验证

确定性回归在 HTTP 101 已发出、`Accept` 尚未返回的窗口暂停升级，先关闭 server 再恢复升级。修复前稳定复现遗漏，修复后检查 WS/WSS、握手认证和未认证连接以及重复关闭。

2026-11-13，Windows amd64、Go 1.27.3、Node.js 24.22.1：

- 固定时序用例在未修复代码上稳定触发遗漏；修复后四种 WS/WSS 与认证组合连续 30 轮通过，共 120 次，包含重复关闭。
- `scripts/verify.ps1` 通过两个前端的测试和构建，以及根 module、desktool、minigame 三个 module 的完整 Go 回归。
- WebSocket、HTTP/TLS adapter 与 proxy runtime 的 `go vet` 通过；Go 依赖校验与格式检查通过。

当前环境没有 C 编译器，未运行 `-race`。外部 NATS 未配置而按原脚本跳过；真实 Redis、ACME/Pebble、公开 CA、原生桌面和安装器不属于本补丁的专项运行验收。根标签发布后再用真实远端模块校验与消费确认版本可获取，不以本地替换作为发布依据。
