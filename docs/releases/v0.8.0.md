# v0.8.0：独立凭据、账号会话与连接认证

日期：2026-11-17。基线：v0.7.1 / 254b8497a77d9ea015891c88502cb615be736d64。
本版本提供下列框架实现；具体业务项目接入仍需独立验收。
真实微信应用、短信供应商及多实例挑战存储仍需宿主集成，不将本地协议测试描述为真实渠道验收。

## 行为变化

凭据验证、可选账号中心、Proxy 连接认证分层。外部系统保留原 token、字符串账号及可选 session，
通过应用适配进入 UserRuntime，不依赖 AIFD 账号表或票据格式。

注册与登录分开，注册默认拒绝；绑定/解绑使用重新认证和身份版本比较。
登录索引直接指向 account_id；解绑不撤销会话。首版支持单会话与账号 epoch 撤销，无 binding ID 或按绑定撤销。
Proxy 必须明确检查策略；初次认证完整执行，后续重检覆盖空闲和纯推送连接，到期后拒绝新的业务写入。

## 消费者迁移

本次按不兼容旧数据和协议的边界实现，没有旧存盘数据自动迁移或兼容适配层。

| 消费面 | 所需适配 |
|---|---|
| Account API | 用 credential.Verifier、显式 Register/Login、RegistrationPolicy、SessionRef 替代旧自动建号流程；设置 BackendID/Audience/IndexKey |
| Redis | 新 space、HMAC 索引、主档 revision/epoch 与独立 session；旧数据不能直接复用。主节点无缓存读取，保留 NoRetry，显式处理 ErrResultUnknown |
| TokenIssuer / Authenticate | 同一权威会话源；签名 payload 带 backend/audience/session/时间；完整检查后映射业务 UID；外部系统可保留原格式 |
| WebSocket | 提供有效 ValidUntil 与明确 AuthCheckMode；Periodic/PerRequest 注入 AuthRevalidator；不按 session 有无自动选择策略 |
| 业务 Runtime | 在可信来源及连接租约门禁之后读取 AuthContext；租户、权限和业务准入不由 UID 映射取代 |
| proto / 生成物 | 重生成 accountpb、Proxy Go/Web PB；minigame auth/player PB 和客户端同步，不能混用旧登录载荷 |
| Minigame | client/robot 请求服务端 demo 票据；本地演示入口不具备生产身份验证，多 proxy 必须共享权威账号事实 |
| 渠道宿主 | 注入短信 Sender、共享挑战 Store、微信应用配置与回调路由；本地 MemoryStore 仅是参照实现 |

## 复验入口与限制

在独立测试环境设置 AIFD_ACCOUNT_REDIS_ADDR、AIFD_ACCOUNT_REDIS_CLUSTER_ADDRS（逗号分隔）和 AIFD_NATS_URL。
Go race 在 Windows 需要可用 C 编译器；前端实际 Node 需满足 package.json，而非仅检查 PATH 上的版本。

```powershell
go test -race -count=1 -timeout 120s ./aifd-account/... ./aifd-proxy/... ./aifd-examples/external-auth
go test -race -count=1 -timeout 120s ./aifd-examples/minigame/internal/app
pwsh -NoProfile -File ./scripts/verify.ps1
```

本次真实 Cluster 使用 Windows Redis 8.6.7，验证跨分片与网络响应丢失，不覆盖生产 Linux、复制故障切换或容灾配置。
Redis 分步操作只承诺已确认步骤；跨 key 非原子，结果不明需核实，受控残留索引恢复不等于线上自动修复工具。
短信未接供应商、微信未提供测试应用/code；挑战共享存储由宿主实现，未验收多实例挑战部署。
无原生桌面 UI 变更，本次没有执行窗口/安装包验收。

业务接入须明确唯一账号与会话事实源，并完成所选渠道的真实联调。
